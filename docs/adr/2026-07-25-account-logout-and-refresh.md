# ADR-001: 账号退出按钮位置与刷新时机

## 状态
已接受

> **2026-08 更新**：本插件**不做多账号**。账号区域已移除多账号下拉框（`account_combo_`）及相关服务（`get_account_list` / `switch_account`），仅支持单一登录态；配置文件中的历史多账号数据仅作兼容保留，不提供切换入口。下文涉及多账号的描述均已过时，以本更新为准。

## 上下文

B站直播工具 OBS 插件需要进行两项 UX 改进：

1. **退出按钮**：需要在任何登录态下提供退出入口（插件为单账号模型，无账号切换）
2. **账户刷新**：OBS 启动时恢复会话使用的是本地缓存数据，需要启动后自动从 B站 API 刷新最新数据

两项改进的目标是提升用户信任感（可见的退出按钮）和数据时效性（启动刷新）。

## 决定

### 决定 1：退出按钮位于标题行右上角

**选择**：将退出按钮放置在标题 "B站直播工具 - OBS 插件" 同一行的右侧。

**替代方案及排除理由**：

| 方案 | 排除理由 |
|------|----------|
| 账号 GroupBox 内部（原位置） | 已随多账号下拉框（`account_combo_`）一同移除；插件为单账号模型，无账号切换区域 |
| 面板底部状态栏旁 | 视觉上不显著，容易被忽略；退出按钮作为高频操作不应放在低关注度区域 |
| 独立菜单栏 | OBS 自定义 dock 无原生菜单栏支持，需引入 QMenuBar + 额外空间成本 |
| OBS 工具栏按钮 | 需要调用 `obs_frontend_add_tools_menu_item`，但 API 不支持按钮 UI，仅支持菜单项 |

**理由**：
- 标题行是面板最显著的位置，用户自然关注的视觉锚点
- 靠右对齐符合桌面应用"关闭/退出在右上角"的认知惯性
- 实现成本最低：仅需将独立 QLabel 改为 QHBoxLayout(title + stretch + button)，约 15 行变更
- 不引入新控件类型或破坏现有布局层次

### 决定 2：刷新时机选 FINISHED_LOADING 后 dock_load 完成时

**选择**：在 `plugin-main.cpp:dock_load()` 函数尾部、`check_live_status()` 之后，用 `QTimer::singleShot(500ms, ...)` 延迟触发刷新。

**替代方案及排除理由**：

| 方案 | 排除理由 |
|------|----------|
| `dock_load()` 中同步调用 | 阻塞 dock 挂载和 OBS 界面渲染，违反 PRD "非阻塞" 要求 |
| `init_current_user()` 中调用 | 服务层不应负责 UI 时机决策，且此时 dock 尚未创建 |
| 周期性刷新（定时器） | 过度设计，增加不必要的网络开销；用户信息变化频率远低于启动频率 |
| 用户在 dock 上手动刷新 | 需要额外 UI 控件，且用户通常不会主动刷新 |

**理由**：
- `OBS_FRONTEND_EVENT_FINISHED_LOADING` 是 OBS 提供的标准"一切就绪"信号，语义最匹配
- `dock_load()` 已在 `on_login_done(cached_data)` 中展示了缓存数据，延迟刷新仅做增量更新
- 500ms 延迟确保 OBS 窗口、dock 面板已完全渲染后再执行 HTTP 调用
- 刷新是 fire-and-forget 操作，不阻塞后续事件处理

### 决定 3：刷新失败采用静默降级

**选择**：`refresh_current_user()` 返回 `code != 0` 时，不弹出任何错误提示，UI 保持缓存数据不变。

**替代方案及排除理由**：

| 方案 | 排除理由 |
|------|----------|
| 弹出 QMessageBox 错误对话框 | 侵入性强，打断 OBS 使用流程；网络波动时反复弹窗极其糟糕 |
| status_bar_ 显示红色错误 | 增加用户认知负担，错误信息对用户无实际帮助（"网络错误"没有可操作性） |
| 重试机制 | 过度设计；B站 API 偶发故障不应在客户端处理，用户重启 OBS 即为重试 |

**理由**：
- 刷新是**增强操作**（improvement），不是关键路径（critical path）。本地缓存数据已可用
- 用户对 B站 API 的网络问题没有控制力，错误提示是噪音而非信息
- OBS 插件应遵循"静默辅助"原则，不成为干扰源
- B站开播/停播等关键操作已有错误提示（`do_start_live()` / `do_stop_live()`），不应混同

### 决定 4：`verify_group_` 不需要在 `do_logout()` 中额外显式隐藏

**选择**：不修改 `do_logout()` 中的人脸验证面板隐藏逻辑。

**理由**：
- `do_logout()` 调用链：`do_logout()` → `set_logged_out()` → `verify_group_->hide()`（bili-dock.cpp:475）
- `on_login_done()` 已调用 `verify_group_->hide()`（bili-dock.cpp:368）
- 登出后所有登录态 UI 均被 `set_logged_out()` 隐藏，人脸验证面板已包含在内
- 无需重复调用

## 后果

### 正面

1. **退出按钮始终可见**：消除单账号用户找不到退出入口的困惑
2. **启动时自动刷新**：用户每次打开 OBS 看到的是最新数据（等级、关注等变化会被感知）
3. **零新依赖**：两个功能均不引入新的库或框架
4. **低侵入性**：总计 ~50 行变更，仅 3 个文件
5. **降级友好**：网络异常时用户体验不变差（缓存数据仍可用）

### 负面

1. **延迟同步的 UI 短暂阻塞**：刷新 HTTP 调用阻塞 UI 线程约 1-2 秒（仅在启动后 500ms 发生）。若未来网络延迟增加或 B站 API 响应变慢，可升级为 `std::async` 方案
2. **`account_combo_` 已移除**：多账号下拉框及相关服务（`get_account_list` / `switch_account`）已删除，`do_logout()` 从 `cfg_->current_uid` 获取当前账号

### 后续优化

- 若 1-2 秒阻塞成为问题：升级为 `std::async` + `QTimer` 轮询方案（约 +30 行，无新依赖）。
- 若需要手动刷新入口：可在用户信息区域添加小刷新图标按钮
